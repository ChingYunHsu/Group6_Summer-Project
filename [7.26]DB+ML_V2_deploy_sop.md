# ClearPath V2 local deployment SOP

Last updated: 2026-07-26

This SOP deploys locally. It publishes V2 forecasts for the six medical venue
types `healthcare`, `clinic`, `hospital`, `pharmacy`, `dentist`, and
`laboratory`. AEDs and restrooms intentionally receive no V2 forecast.

The SerpAPI cohort is used only for supervised evaluation. Medical types that
are absent from that cohort are still served through the model's cold-start
path; do not describe their per-type accuracy as validated.

## Prerequisites

From the repository root, create the shared Python environment once. Any
supported local Python 3.11+ is acceptable.

```bash
cd /path/to/Group6_Summer-Project
python3 -m venv .venv-1
source .venv-1/bin/activate
python -m pip install --upgrade pip
python -m pip install -e backend

# Required only when restoring OSM source data via the optional notebook.
python -m pip install jupyter
```

The repository must contain these Git-tracked deployment inputs:

- `venues_export.sql` and `docs/venues_export_20260718_schema.md`;
- `Data+ML/test/7.13-7.18/output/serpapi_v2_labels_20260716/`;
- `Data+ML/test/7.13-7.18/output/serpapi_repeat_audit/`.

No raw `data_source` bundle is required for the standard local deployment.

## Fresh local database

Use this only when rebuilding the local database. It deletes local MySQL and
Redis volumes; do not use it for an existing database you need to keep.

```bash
cd /path/to/Group6_Summer-Project
docker compose down -v
docker compose up -d mysql redis
docker compose exec -T mysql mysqladmin ping -h localhost -uclearpath_app -pclearpath_app

# Give every legacy positional venues INSERT chunk explicit column names before importing it.
.venv-1/bin/python tools/convert_venues_export.py venues_export.sql venues_export_converted.sql
docker exec -i clearpath-mysql mysql -uclearpath_app -pclearpath_app clearpath \
  < venues_export_converted.sql

# Reapply all post-schema migrations, including the MySQL-8.4-safe 012 and
# the fixed 200-venue hospitals-first mock accessibility fixture.
bash docker/mysql/apply_migrations.sh
```

For a fresh database, Docker's init scripts create the base schema first. The
converted snapshot is then imported, and `apply_migrations.sh` applies the
idempotent post-schema migrations. Do not import the raw positional dump.

### Local-demo wheelchair fixture

`013_seed_mock_wheelchair_support.sql` is retired and intentionally a no-op.
`014_seed_mock_medical_accessibility_coverage.sql` replaces old mock rows
with 200 deterministic `full_access` medical demo labels. It selects every
hospital first, then fills the remaining slots from other medical types. They
are explicitly marked `source=mock`; do not report them as verified real-world
coverage.

### Optional: local demo language labels

```bash
docker exec -i clearpath-mysql mysql -uclearpath_app -pclearpath_app clearpath \
  < docker/mysql/scripts/seed_mock_medical_languages.sql
```

The seed fills only null/empty `language_tags`; it reports 50 matching mock
venues when its target records exist.

## Existing local database (patch deployment)

Do not run `docker compose down -v` and do not re-import `venues_export.sql`
when `SELECT COUNT(*) FROM venues` already contains the snapshot data.

```bash
cd /path/to/Group6_Summer-Project
docker compose up -d mysql redis
bash docker/mysql/apply_migrations.sh
```

If the database has only the original five smoke-test venues, follow the
fresh-database snapshot conversion/import section instead.

## Publish traffic baseline and V2 curve

The NYC SODA traffic baseline is an hour-of-day profile for the model; the
source year is not a current-status time window. V2 publishes 13 points per
eligible venue: now through `+12h`. The API returns the upcoming 12-point
forecast series.

```bash
cd /path/to/Group6_Summer-Project

.venv-1/bin/python Data+ML/test/6.15-6.20/src/busyness_ingestion.py --year 2025

cd Data+ML/test/7.13-7.18
../../../.venv-1/bin/python forecast_v2_pattern.py \
  --labels output/serpapi_v2_labels_20260716/serpapi_popular_times_weak_labels.csv \
  --legacy-labels output/serpapi_repeat_audit/legacy_cached_baseline.csv \
  --output-dir output/v2_pattern_traffic_latest \
  --publish
```

Accept the publication only when the pre-publish audit reports all expected
medical types present in the current database and:

```text
future rows = eligible venues × 13
published = future rows
```

The actual count is deliberately dynamic: a snapshot may contain 1,083,
1,086, or another number of medical venues. A fixed 964/12,532 assertion is
not a release gate.

## Start API and web client

Create `backend/.env` from `backend/.env.example`, setting at least `API_KEY`,
database credentials, `JWT_SECRET`, and `MEDICAL_PROFILE_ENCRYPTION_KEY`.

```bash
# Terminal A
cd /path/to/Group6_Summer-Project/backend
../.venv-1/bin/python src/app.py
```

```bash
# Terminal B
cd /path/to/Group6_Summer-Project/frontend/web
npm install             # first run or lockfile change
export VITE_API_KEY='same value as backend API_KEY'
npm run dev
```

Open `http://localhost:5173/`. Vite proxies `/api` to `127.0.0.1:5000`.

## Basic acceptance checks

```bash
export CLEARPATH_API_URL='http://127.0.0.1:5000'
export API_KEY='your-local-api-key'

curl -fsS -H "X-API-Key: $API_KEY" "$CLEARPATH_API_URL/api/v1/venues" \
  | python3 -c 'import json,sys; p=json.load(sys.stdin); assert p["count"] == len(p["items"]); assert p["count"] > 5; print(f"PASS: {p[\"count\"]} venues returned")'

cd /path/to/Group6_Summer-Project/Data+ML/test/7.13-7.18
VENUE_ID=$(sed -n '2p' output/v2_pattern_traffic_latest/prediction_curve_v2_pattern.csv | cut -d, -f1)

curl -fsS -H "X-API-Key: $API_KEY" "$CLEARPATH_API_URL/api/v1/venues/$VENUE_ID/busyness" \
  | python3 -c 'import json,sys; p=json.load(sys.stdin); b=p["busyness"]; assert b["data_mode"] == "forecast"; assert b["forecast_source"] == "busyness_forecasts"; print("PASS: current V2 busyness")'

curl -fsS -H "X-API-Key: $API_KEY" "$CLEARPATH_API_URL/api/v1/venues/$VENUE_ID/busyness/forecast" \
  | python3 -c 'import json,sys; p=json.load(sys.stdin); assert p["data_mode"] == "forecast"; assert p["forecast_source"] == "busyness_forecasts"; assert p["model_version"] == "forecast-v2"; assert len(p["forecast"]) == 12; print("PASS: V2 12-hour forecast")'
```

Finally, open the map without filters. Its venue count must match the list API.
The Clinic filter must include `clinic`, `healthcare`, `dentist`, and
`laboratory`; Hospital and Pharmacy remain separate filters.
